## Описание классов

### `FloatRange` — класс-итератор (№10)

Аналог `range` с дробным шагом, в том числе отрицательным. Класс реализует протокол итератора: `__iter__` возвращает сам объект, `__next__` отдаёт следующее значение или выбрасывает `StopIteration`. Значение вычисляется как `start + index * step`, а не накапливается сложением, поэтому `FloatRange(0, 1, 0.1)` даёт ровно 10 чисел без «хвостов» вида `0.30000000000000004`.

### `Student` — «Студент» (№2)

Хранит ФИО, группу и оценки. Оценки инкапсулированы: они лежат в защищённом атрибуте `_grades`, добавляются только через `add_grade` с проверкой типа и диапазона 2–5, а наружу отдаются через свойство `grades` в виде кортежа, поэтому изменить их в обход проверки нельзя. `info()` возвращает текст с информацией, `print_info()` выводит его на экран. Также переопределены `__str__` и `__repr__`.

### `Counter` — счётчик (№8)

Счётчик с шагом и необязательными нижней и верхней границами. Методы `increment(times)`, `decrement(times)` и `reset()`. При выходе за границу выбрасывается `ValueError`, а значение остаётся прежним. Свойство `value` доступно только для чтения.

### `Product`, `Cart`, `Order` — система заказов (повышенное №3)

- `Product` — товар с артикулом, названием и ценой. Цена хранится в `Decimal` с округлением до копеек. Товары сравниваются и хешируются по артикулу, поэтому их можно использовать как ключи словаря.
- `Cart` — корзина с методами: добавить, уменьшить или убрать товар, узнать количество, получить точную сумму, очистить. `len(cart)` возвращает общее число единиц товара.
- `Order` — заказ из корзины. При оформлении запоминает позиции и сумму, очищает корзину и получает уникальный номер (счётчик на уровне класса). Статусы меняются по схеме `new → paid → shipped` или `new → cancelled`; недопустимый переход вызывает `RuntimeError`. Метод `receipt()` формирует чек.

### Unit-тесты по TDD (повышенное №10)

Каждый класс написан по циклу «красный → зелёный»: сначала отдельным коммитом `test: add failing tests ...` добавлялись тесты, затем коммитом `feat: ...` появлялась реализация. Порядок виден в истории коммитов. Результаты запуска тестов на каждом из этих коммитов (падение до реализации, успех после неё) собраны в [TDD.md](TDD.md).

Тесты проверяют и обычную работу, и граничные случаи: пустые данные, неверные типы, выход за границы, недопустимые переходы статуса заказа, точность денежных расчётов, одноразовость итератора.

## Какие принципы ООП использованы

| Принцип | Где |
|---|---|
| Инкапсуляция | `_grades` и свойство `grades` в `Student`, `_value` и свойство `value` в `Counter`, закрытый словарь `_items` в `Cart` |
| Конструктор `__init__` и проверка данных | все классы |
| Специальные методы | `__iter__`/`__next__`, `__eq__`/`__hash__`, `__len__`, `__int__`, `__str__`/`__repr__` |
| Атрибуты класса | `Order._next_id`, `Student.MIN_GRADE`/`MAX_GRADE` |
| Композиция | `Cart` хранит `Product`, `Order` создаётся из `Cart` |
